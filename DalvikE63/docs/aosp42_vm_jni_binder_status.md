# Stato E63/AOSP 4.2.2: VM, JNI, Binder, servizi (incompleto)

`/dev/binder` su Android è un **nodo di dispositivo per IPC**, non una partizione fisica o logica. Nel guest E63 il router `vfs_mount.c` lo classifica come endpoint virtuale `E63_MOUNT_IPC` con relativo vuoto: non viene aperto un file o mappato un settore su C:. `/system` rimane guest persistente e di sola lettura; i dati e le cache verificate risiedono prevalentemente su C:, non nell'intera RAM.

## Componenti implementati e collegati al SISX sperimentale

- `symbian/runtime/aosp_object_vm.c`, `e63_ui_store.cpp`: esecuzione reale di piccoli costruttori e metodi DEX tra APK originale, framework.jar e core.jar, tutti SHA-pinnati. Non include Activity e rendering Java.
- `symbian/runtime/third_party/aosp42_jni.h`: header JNI originale AOSP `libnativehelper` `android-4.2.2_r1.2` (SHA-256 `8ade5e217b1e55608a02bd5497ec79e7b47ec9dbfa89b96fd5ad899b131e473f`, licenza Apache 2.0). `jni_bridge.c` implementa solo l'ABI JNI 1.6 di `GetVersion`, `FindClass` per classi DEX già autenticate, `RegisterNatives`, `UnregisterNatives` e la chiamata nativa static `()I`. `boot_method.c` controlla flag `ACC_NATIVE|ACC_STATIC`, metodo esatto e assenza di `code_item`, rifiutando falsi positivi. Sul target `e63_boot_store.cpp` registra ed esegue `android.os.Process.myPid()` usando l'ID del processo Symbian (tasto `*`). **Non esiste ancora JNI completa né processo Android virtuale.**
- `symbian/runtime/binder_ipc.c`: segmento *limitato* del formato AOSP 4.2 `Parcel` (String16, strict-mode interface token, flat_binder_object a 32 bit con metadati offset) e transazioni 1–4 di `IServiceManager` sul context handle 0. Rifiuta handle forgiati, registrazioni da UID non di sistema e lookup di servizi non registrati, revoca handle/servizi quando il proprietario chiude. `e63_binder_port.cpp` fa passare `Parcel` via veri `RSessionBase`/`CServer2` tra thread Symbian con controllo `SecureId`; **non usa file o driver su /dev**. Il tasto `B` controlla che `activity` sia ASSENTE: non inventa servizi Android. Non implementa ancora `open/ioctl` POSIX, il driver kernel o `libbinder` completo.
- `e63android-aosp42-jni-binder-preview.sisx`: SISX sperimentale Symbian FP1, versione 0.6, 44 payload AOSP/guest fissati e verificati byte-per-byte. Compilato GCCE, firmato localmente e analizzato come struttura SISX. **Non testato/installato sul Nokia, non Android completo.** Il file grande e la relativa chiave di firma, entrambi sotto `build/`, sono spariti al precedente snapshot; dai sorgenti preservati è stato rigenerato un SISX equivalente ma con nuovo certificato e SHA-256 `4c9a312e19789c394e072825f7b9e95a82efbaa9c6dfcd0bd30cf6a033db55ff`. La copia persistente sarà un asset GitHub Release, NON un file durevole nel workspace (capienza snapshot). Leggere `release/experiments/LEGGIMI-JNI-BINDER-PREVIEW.md` prima di qualunque installazione. Release 0.2, APK, JAR, progetto Java originale e MIDP conservati.

## Blocchi reali tuttora aperti

JNI oggetti/riferimenti/class loader e bytecode generale/GC/eccezioni; equivalenza Binder completa Linux↔Symbian (endpoint fra processi guest, driver semantics, callback remote, FD, morte, oneway, UID Android); JNI `Binder.init`, `Parcel` native, `BinderInternal.getContextObject`; avvio di `SystemServer`, `ActivityManager`, `PackageManager`, `WindowManager`, input e risorse; lifecycle di Activity e rendering delle `View` autentiche. Non avviare UI shim e non dichiarare Android 4.2 funzionante. `SystemUI.apk` conserva il requisito di errore simulato.

I sorgenti necessari sono ricreabili sotto `build/` escluso dallo snapshot mediante `bootstrap_framework42_only.py`, `bootstrap_android42_dependencies.py`, `bootstrap_aosp42_ui.py` e `bootstrap_aosp42_host_tools.py` (solo repository in allowlist, tag/commit fissati; firma GPG dei tag non verificata). `tools/build_aosp42_jni_binder_preview_sis.py` rigenera il preview con SDK Nokia installato localmente. Verifica sviluppo: `python3 -m unittest discover -s tests -p 'test_*.py' -q` = **153 test, 1 saltato, nessun errore**; build e verificatore SISX riusciti. Non sono prove E63: serve il telefono fisico o log del dispositivo per confermare l'avvio.
